# 轮渡遗留物的双岸交接与领取核验的演练来源

这里提供独立来源的本地合成记录，与实际单位、个人和线上业务无关。

## 本地运行

使用 Node.js 22.23.4。只使用 Node.js 自带的运行库。

执行 `npm test` 检查合成来源的接口。执行 `npm start` 启动来源，默认监听 `127.0.0.1:4100`，可通过环境变量 `PORT` 调整端口。访问根路径可看到来源名和当前回放阶段。

## 接口资料

| GET 路由 | 来源约定 |
| --- | --- |
| `/source/cabin` | 位置只在航次内有意义。物件 P 和外袋 BAG 是独立身份。分类和私下核验字段由清舱人员登记。 |
| `/source/storage` | count 只证实列出的袋与物件。released 表示实物离库，该编号不再可领。 |
| `/source/counters` | 申请点不能替代物件实际保管地。checked 属私下核验部分，publicFields 可向查询者展示。 |

查询参数 `offset` 是从零开始的页偏移，`limit` 默认 3，取值 1 至 100。响应中的 `records` 含 `record` 来源记录键、`availableFrom` 首次出现的回放阶段、`kind` 记录类型、`payload` 业务字段。来源记录键与业务身份分别定义。`next` 为下一页偏移，末页为 `null`。回放阶段中的记录按到达顺序可查。

控制员通过 `POST /control?stage=2` 切换到第 2 阶段，服务会保留更早已可查的记录。每次换阶段后按根路径返回的 `stage` 确认切换成功。

柜台从 `GET /counter-receipt` 按 `point` 与 `claim` 查实物交出凭据。202 表示仍在确认，404 仅表示这一柜台当前无回执。收到 200 时可以查到交出时刻、柜台、物件和申领编号。

## 归集核验台

在来源之上持续收集三路记录并给出双视角结论，分三个文件：

- `desk-core.mjs`：投影核心。归并清舱、保管台、柜台记录，推导物件与登记的状态。只依赖记录本身，不做读写。
- `desk-collector.mjs`：收集器。分页拉取三个来源并去重，回放阶段推进后自动补收；对存在有效保留的登记按（保管点, 登记）追问交出回执。
- `desk-server.mjs`：查询接口。先 `npm start` 启动来源，再 `npm run desk` 启动本服务（默认 `127.0.0.1:4200`，`SOURCE_URL`、`DESK_PORT` 可调）。

| 路由 | 含义 |
| --- | --- |
| `GET /desk/claims` | 服务台内部视图：仍在候选、可去哪个点领取、已实际交出、需重核，含私下核验 |
| `GET /desk/public/claims` | 台面公开视图：只含可公开范围，不含私下核验特征 |
| `GET /desk/claims/{登记}` | 单笔登记详情 |
| `GET /desk/objects` | 每件物件当前状态与沿革 |
| `GET /desk/supplements` | 相似线索催补清舱资料的清单 |
| `GET /custody/objects` | 保管台视角：每件当前责任方与交接缺口 |
| `GET /custody/bags` | 按封装记录查起：每袋沿革、是否两次拆录、袋内每件责任方 |
| `GET /events` | 已归集的原始记录 |
| `POST /poll` | 手动轮询一次（常驻模式下也会按间隔自动轮询） |

归集时执行的规则：盘点未列出的物件不能报作遗失；旧袋与新袋的关联只认拆装回执的逐件点交；保留须保管事实与私下核验相符，且保留期内两个柜台不能对同件分别办理；交出以交件班组确认（回执 200 或 released）为准，确认期间保留到期也不放件；柜台明确未交且实物仍在保管点才可重新办理；实际交出后保管链终止，之后整理旧袋资料只更正沿革；一袋两次拆录时受修订影响的物件转柜台重核，不凭新袋状态自动移交；已领物件确认误交时保留回执交原柜台逐件处理，不回填在库。
